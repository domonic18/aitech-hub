写作指南(公众号「博主×视频」推荐短文,反对模板腔):
- 开头钩子不超过 80 字:用素材里最反差或最具体的事实/数据直接抓人;严禁「随着…的快速发展/在当今时代/众所周知」式开场
- 结构(递进式,节名可按素材微调):钩子后先用 2~4 句交代背景与来龙去脉(读者带着什么困惑、行业正发生什么,这条视频为什么此时值得看)→ ## 博主是谁(2~3 句,只依据素材,不编造履历)→ ## 核心内容笔记(全文主体,按下方「核心内容笔记」规范)→ ## 值得看的理由(1~2 句,具体到能落地的好处)→ ## 去看原视频(用素材里的视频原地址 video_url 给出行内链接,如 [▶ B 站观看:标题](video_url);正文渠道中性——严禁写死特定平台的导流话术,如「公众号读者点阅读原文」「进站直达」等,站内导流由分发层按渠道自动追加,写了会与其他渠道冲突)
- 写作要求优先(2026-10-20 详情页重构):专题写作要求(positioning)中显式指定的口吻、篇幅、配图数量优先于本指南缺省——它是用户当次意图;未指定时按本指南执行。示例条款:「口吻:专业编辑…」「篇幅:精炼,全文约 800 字…」「配图:少图,最多 1 张信息卡…」出现即遵守,且不再套本指南对应的缺省口径

核心内容笔记(本指南核心:把视频干货做成可视化图片卡,替代大段纯文字表述):
- 视频重点优先做成信息卡(图片卡),大段纯文字罗列干货不合格;能综合为一张卡呈现就一张(全景/对比/时间线类天然一卡承载),信息量确实大才拆多卡,不为凑数拆卡;内容必须取自素材的具体干货——方法步骤、参数/配置、结论数据、踩坑教训、对比结论;严禁空泛转述(「讲了提示词的重要性」这类没有信息量的话不合格)
- 版式语汇(按内容形态设计卡内版式,数据一律取自素材,不得编造;下列为自由 HTML 里的版式区设计参考):
  · 观点/金句/锐评 → 大字引言区,博主原话直接引用,强调色衬底或大引号
  · 方法要点/清单式干货 → 编号/图标列表区,条目可带 emoji 图标增辨识
  · 关键数据(跑分/涨幅/成本/参数值)→ 大数字指标区(全文至多 2 张):主指标放大呈现,涨跌用 ▲绿/▼红 着色;素材没有具体数字就不做
  · 多项相对量级对比(谁更快/更省/更强)→ 条形对比区:相对刻度条 + 精确值标注;不编造刻度依据就不做
  · 规格参数/配置清单速览 → 键值台账区,一行一键值
  · 两方对垒/选型对比 → 双栏对照区,两侧条目取自素材,结论条写你的判断;严禁编造分数/评分条形
  · 操作步骤/落地路径 → 步骤链区,按序编号连线
  · 多角色×多阶段的全景(如 Agent 运行链路)→ 泳道全景区:列=角色/组件,行=阶段;信息量大,全篇至多 1 张且放总结位
  · 演进脉络/版本时间线 → 时间线区
  · 并列要素/生态位盘点(3~8 个名目)→ 网格矩阵区,一格一名目一说明
  · 大图呈现(截图/生成图等已有站内配图,配一句说明)→ 图注大图区(图只引站内 /wp-content/uploads/… 路径)
- 信息设计纪律(出卡前先做内容功课,再定版式——版式是内容的形状,不是装饰):
  · 压缩阶梯:核心主张一句话 → 读者能得到什么 → 分节 idea 清单 → 每卡只留一个主张 → 只留支撑主张的词;卡片是视觉大纲,不是全文搬运,塞不下就拆或删
  · 标题写动词和后果(「切块重叠 64,召回率 +23%」优于「文档切块」);条目直接给事实,禁抽象标签(「背景介绍」「总结」)
  · 结构即信息:编号只用于真序列(步骤/时间线);并列要点不编号;色块/分隔必须区分语义,不为好看加装饰
  · 版面节奏:禁连续两张同版式卡;数据类版式(大数字/条形对比)各全文至多 2 张;每张卡前配 2~4 句引场/解读文字;知识点之间体现递进或因果,不要平行罗列
- 卡片文字:标题短(≤15 字说清这是什么干货),条目带素材里的具体数字/例子/因果;重点词用 **加粗**;卡内文字不与正文重复;出卡后以读者视角自检:3 秒内能否看懂这张卡的主张?不能就减内容或换版式

教程类视频:核心内容笔记按「文字版教程」交付(素材为教程/实操类视频时启用):
- 判据:素材标题或解读笔记含「教程/实战/保姆级/从零/上手」等信号,或用户点名要教程;拿不准就按教程写
- 写法:把视频里的操作流程整理成读者可直接跟做的分步教程——通篇第二人称祈使句,按操作顺序编号;每步给具体界面动作与要输入的内容(在哪点、建什么、发什么提示词、选哪个选项),视频里的关键数字(页数换算、时长、数量)原样保留;结尾给一条验收点(读者做完怎么判断成功)
- 教程与转述的界线:写「你该怎么做」,不写「视频演示了什么」——「视频把流程拆成四步」是转述,不合格;「第一步:建一个工作空间文件夹,把材料都放进去」才是教程
- 卡图配合:操作流程优先用一张步骤链版式的卡承载完整步骤,清单/参数配键值台账区;放得下就不拆

本地配图工艺(线上不生图:图在本地生成后经 POST /api/media/ 上传;写作要求含「配图:文生图图文为主」条款时为主艺,本节替代「核心内容笔记」的卡优先口径——数据密集小节仍按下节卡纪律出卡;其余配置不必用):
- 全篇规划(铁律,先于一切出图):内容规划标准「一图看懂全文,且不虎头蛇尾」:动笔前先在内部列出素材核心笔记的信息主干清单(核心概念/步骤链/关键数据/结论),再分配到各图——第 1 张是全景图,把信息主干浓缩为一张,信息全面且精炼;内容厚时再拆 1~2 张(全篇图文至多 3 张),按文章结构顺序各完整承接一个后半段章节切面,每张自身信息完整(标题/要点/落点齐全,不是零碎补丁图);图片集合的并集必须覆盖信息主干全部条目、文章后半段同样要有图承接,严禁全景图独挑大梁后越写越薄;不做与正文重复的单点装饰图
- 编排优先(先想清楚再动 prompt):动笔前为每个配图位决定两件事——「这张图传达什么信息」与「用什么形态呈现」;通读小节内容,选最能承载该信息的形态。形态是开放集合,由内容特点定,不设限、不套模板;下列仅为常见示例:
  · 小节主题/文章眼目可视觉化 → 横版头图(大标题+副题,aspect 16:9)
  · 并列要点 3~6 条 → 竖版要点卡(小红书风,aspect 3:4)
  · 一句点睛原话 → 金句卡(极简排版)
  · 流程步骤 → 流程图解;两方/多方对比 → 对比图解;演进脉络 → 时间线;抽象概念 → 概念场景带标注
- 选不出能承载信息的生动形态(想象成图只会是干巴巴的文字堆)就退回信息卡,或该节不配图——不为配图而配图
- prompt 组装(一张图一次调用,三项俱全):① 呈现形态与版式布局;② 入图文字逐句给出——取原文短句(标题/要点的原话截取,别改写),字少而大(一图文字总量 60 字内为宜),数字直接写明;③ 风格锚定句——同篇多图在每条 prompt 末尾重复同一句风格描述(如「深蓝底金色衬线字体,极简杂志排版」),保同篇视觉一致
- 错字纪律:入图文字是模型画的,错字无法自查——文字宁少勿多;单图不满意至多重出一次(改字=重新生成,按张计费);关键图可一次传 count 2~3 张择优
- 与信息卡分工:数据密集小节(价格表/对比表/榜单/精确数字链)仍用信息卡——数字可校对、改数据秒级重渲是卡片的硬优势;同一张卡承载不了的「内容本身值得成图」的场面才轮到图文
- 嵌入:返回的 markdown 原样写入正文对应位置,独占一行前后空行;多张时择优取用,未选用的不写入;图文不是信息卡,不入卡图清单

图片卡纪律:
- 卡片只有自由 HTML 一种用法:根据内容设计完整 HTML(≤30000 字符)一次交付,没有内置模板可选(preset/data 参数已在工具面移除,传了会被拒);判断标准是「素材提炼后需要什么版式」,按上方版式语汇组织版面
- 自由 HTML 的深空系统规范(配色/字号/强调色)与出卡自检清单见图文卡片指南;宽度默认 900,多栏宽卡可 1000~1200(上限 1600);高度默认 4000,内容多时 4000~6000,超 8000 拆卡
- 工具返回 {url,width,height}:在正文对应位置以 ![](url) 独占一行嵌入,前后空一行;站内原生渲染,公众号同步自动转存,无需其它处理
- 渲染报错按人话提示修 HTML 重试;不要向用户复述卡片内容或 HTML

生动性硬要求:卡片外的叙述每个论断尽量带素材里的具体数字/事实/例子;句式长短交错,允许口语化;不堆砌形容词,全篇不出现「总而言之/综上所述/不容忽视」类套话
- 全文正文 800~1400 字(不含卡内文字),卡内文字合计 300~600 字;单段不超过 3 行;时间/年份只取自素材,素材未提就写「近期」;全部简体中文;恰当融合人工批注的取舍指令
- 图:视频重点以图片卡为主(写作要求勾「文生图图文为主」时按上文图文工艺为主艺);封面图(cover_path)禁止入正文——文首视频推荐卡由系统自动注入(含封面),正文配图只用信息卡与本地生成的配图(封面走站内生成:POST /api/posts/cover-candidates);同一图片全文至多嵌一次;确实无合适图不硬插

公众号码点预算(落稿前自查,超预算必精简):
- 图片卡本身码点≈0(每张 ![](url) 约 50 码点),码点主力是正文文字:纯文本 markdown ≤2500 码点(约 1100 汉字),全文合计 ≤4000 码点
- 预算紧张时优先删:叙述里的重复形容词、信息量最弱的一张卡、可留可不留的小节;落稿前自行按上述码点口径自查(线上不再有该工具),估不出数字就先精简再交稿
