# 图文卡片使用指南

## 何时使用卡片

正文需要「视觉强调」的段落优先渲染卡片图嵌入,而非纯 markdown 文字。内容形态 → 版式语汇(自由 HTML 里的版式区设计参考):

- 观点/金句/锐评 → 大字引言区;方法要点/清单 → 编号/图标列表区(条目可带 emoji 图标)
- 关键数据 → 大数字指标区(主指标放大呈现,涨跌用 ▲绿/▼红 着色)
- 多项相对量级对比 → 条形对比区(相对刻度条+精确值标注);规格参数/键值速览 → 键值台账区
- 两方对垒/选型 → 双栏对照区;操作步骤 → 步骤链区;演进时间线 → 时间线区
- 多角色×多阶段全景 → 泳道全景区(信息量大,全篇至多 1 张);并列要素盘点 → 网格矩阵区
- 大图+一句说明(截图/生成图等站内已有配图)→ 图注大图区(图只引站内路径)

一篇 2~4 张为宜(全景/长文可至 5),禁连续两张同版式;普通叙述段、程序性说明不硬插。无合适内容就不插卡。

## 出卡前的内容功课(版式是内容的形状)

- 压缩阶梯:核心主张一句话 → 读者能得到什么 → 每卡一个主张 → 只留支撑主张的词;卡片是视觉大纲,不是全文搬运
- 标题写动词和后果,条目直接给事实,禁抽象标签(「背景介绍」「总结」)
- 结构即信息:编号只用于真序列(步骤/时间线),并列要点不编号;色块/分隔必须区分语义

## 调用纪律

1. 工具:站内 POST /api/cards/render(PAT 或会话;该路由尚未上线时,改为本地出图后经 POST /api/media/ 上传)。返回 {ok,url,width,height,accent,markdown_line},url 已入库。
2. **卡片只有自由 HTML 一种用法**:根据文章内容自己设计完整 HTML
   (≤30000 字符)一次交付;内置模板(preset/data)已在工具面移除,不要尝试
   这两个参数,传了会被 schema 拒绝。宽度默认 900,多栏宽卡 1000~1200(上限
   1600);高度默认 4000,可传 maxHeight 400~8000(内容多时 4000~6000,超 8000
   拆卡)。渲染端宽容:写 HTML 片段即可(html/head/meta/title 等文档级标签自动
   摘除,深空底与中文字体已内置),美观由你按下面的「深空可视化系统」规范写,
   出卡后按自检清单把关:
   - 深空系统(全站卡片统一视觉语言):body 底 #0b1220(可叠 135deg 渐变至
     #161233);文字三级 #f1f5f9(主)/#cbd5e1(次)/#94a3b8(辅);强调色直接取
     工具返回的 accent({main,soft,text} 三色,同篇所有卡恒同组)——main 做形状/
     线条,soft 做色块底,text 做强调字;数字用 font-variant-numeric:tabular-nums;
     装饰至多一种(顶部 accent 短线或一枚弱圆环);禁渐变文字/发光/大面积低对比灰字
   - 样式组织:单个 <style> 块 + class 复用,禁止逐元素重复 inline style;禁
     <script>/<iframe>/外链资源(消毒整体报错);图片只允许站内路径
     /wp-content/uploads/…(从媒体库取,**严禁手写 base64 data URI**);宽度保持默认 900
     (多栏宽卡 1000~1200,上限 1600);style 属性里的 url() 同样只允许 data: 与站内路径
   - 出卡自检(在写 HTML 时逐条过,渲染出来后就不再返工):① 对比度——深底正文至少用
     次级色 #cbd5e1,禁大面积低对比灰字;② 强调色全卡仅 accent 一组,不引第三方色;
     ③ 标题 3 秒能读懂主张;④ 布局自查——用了 class 就必须在同一份 HTML 的 <style>
     里定义它(flex/grid 版式缺样式会塌成单列),一个 <style> 块写全
   - 一次定稿:你看不到渲染成图,凭想象反复重渲只是盲猜。渲染成功即采用;仅当工具报错,
     或返回的 height 异常矮(内容没挂上)/ 超高(先把 maxHeight 调到 6000~8000,仍超再
     拆卡)时修正一次。修正一次仍不满意就交付该卡并说明,禁止连环重渲(同一张卡至多 2 次)
3. **多卡叙事(内容一张卡承载不了就主动拆,不等 413 超高报错)**:预计高度逼近
   maxHeight 上限,或同卡内出现多段版式异质、各自成体系的内容,即按叙事弧拆卡——
   总览主卡 → 核心论证各一卡 → 结论/行动卡;信息量就是拆卡理由,不为凑数拆。
   系列感三件事:全篇恒用同一组 accent 与同一版式语言;卡角可标 N/M 阅读序
   (tabular-nums 小字,阅读序是真序列,不违反「并列要点不编号」);每张独立可读、
   自带完整主张——单抽一张也能直接当图文发布。拆卡不降级:系列主卡保持整版
   设计水准,不因拆卡偷工减料。
4. **双端适配(公众号/小红书)**:公众号正文图 900 宽默认即适配,无需特殊处理;
   素材将手动发小红书或做成图文教程时,改用竖版 3:4 整版设计(宽 1080,
   内容量按高约 1440 规划,可传 maxHeight 1440 防溢出,超高即再拆一张)或方形
   1:1(1080×1080)——一张卡 = 一条可单独发布的图;900 宽横版卡对小红书不友好,
   不要直接投。
5. 嵌入:在正文对应位置以 ![](url) 独占一行引用,前后空行;url 为站内媒体路径,
   公众号同步自动转存。渲染了卡但正文漏嵌 = 白做。
6. 失败自纠:报错是人话指引——消毒违规逐条列出(照改后重调)/ 429 忙(稍后重试)/
   413 超高(拆成多张卡)。不要换别的工具绕行。
