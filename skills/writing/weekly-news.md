写作指南(公众号「周新闻精选」稿,分组综述,每条独立可读):
- 开头三行速览:①②③ 列本周最重要动态,每条一句话讲清「发生了什么+为什么值得在意」;速览与正文严格对应,不出现正文没有的条目
- 结构:速览 → ## 分组小节(按「模型/框架/行业」等主题分组,组名按本周内容定;每条动态一段:结论式导语一句 + 2~3 句展开)→ ## 下周值得跟踪(点一件事,给理由)
- 硬纪律:每条动态交代来源(哪家公司/团队/仓库),时间表述取自素材,未提写「本周」;传闻与证实分开,素材未证实的标「据称」;条目按重要性排序,不按素材挂载顺序堆砌
- 生动性:导语写成结论句(「开源社区出现首个跑通手机端的多模态框架」优于「多模态有新进展」);每条不依赖上下文主语,可单独截图传播;全篇不出现「综上所述」类套话;全部简体中文
- 全文正文 1000~1400 字;单条动态不超过 4 行
- 写作要求优先:专题写作要求(positioning)中显式指定的口吻、篇幅、配图数量优先于本指南缺省——它是用户当次意图;未指定时按本指南执行,示例条款(「口吻:专业编辑…」「篇幅:精炼…」「配图:文生图图文为主…」)出现即遵守,且不再套本指南对应的缺省口径

配图工艺(两类工艺互补非替代):
- 全篇规划(铁律,先于一切出图):内容规划标准「一图看懂全文,且不虎头蛇尾」:动笔前先在内部列出素材核心笔记的信息主干清单(核心概念/步骤链/关键数据/结论),再分配到各图——第 1 张是全景图,把信息主干浓缩为一张,信息全面且精炼;内容厚时再拆 1~2 张(全篇图文至多 3 张),按文章结构顺序各完整承接一个后半段章节切面,每张自身信息完整(标题/要点/落点齐全,不是零碎补丁图);图片集合的并集必须覆盖信息主干全部条目、文章后半段同样要有图承接,严禁全景图独挑大梁后越写越薄;不做与正文重复的单点装饰图
- 配图位编排:为每个配图位先定「这张图传达什么信息+用什么形态呈现」,形态由内容特点定、不设限——头图/要点/金句/对比图解/流程步骤/时间线等只是常见示例
- 数据密集小节(表格/榜单/多组对比/步骤链/精确数字链)优先做信息卡:数字可校对、改数据秒级重渲是硬优势;自由 HTML 单一路径,版式语汇与深空规范见同目录 card-rendering.md(直接 Read 取用);卡片渲染走站内 POST /api/cards/render(该路由尚未上线时,改为本地出图后经 POST /api/media/ 上传);能一张即一张,不凑数
- 内容本身值得成图的场面走本地生成的配图(线上不生图,图字节不过模型上下文):prompt 三项俱全——呈现形态与版式布局、入图文字逐句给原文短句(别改写)、风格锚定句同篇每条复用;字少而大(一图 60 字内),横版 16:9、竖版卡片 3:4;入图文字是模型画的,错字自查不出,一图至多重出一次
- 嵌入纪律:配图 markdown 独占一行前后空行;同一图片全文至多嵌一次;图文不是卡片不入卡图清单;卡图清单当前无处可报(MCP upsert_article 暂无该字段,缺口见瘦身方案 B1)——落稿前自行核对:每张渲出的信息卡都必须已嵌入正文对应位置,漏嵌会在站内退化成普通配图;封面图禁止入正文(文首推荐卡由系统自动注入)

公众号码点预算(落稿前自查,超预算必精简):卡图/图文本身码点≈0(每张 ![](url) 约 50 码点),码点主力是正文文字——纯文本 markdown ≤2500 码点(约 1100 汉字),全文合计 ≤4000 码点;预算紧张优先删最弱小节与重复形容词;落稿前自行按上述码点口径自查(线上不再有该工具),估不出数字就先精简再交稿
