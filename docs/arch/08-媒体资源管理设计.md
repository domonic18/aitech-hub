# 媒体资源管理设计(图片 / 视频 / 清洗)

> 媒体是本站仅次于文章的核心资产。本文定义:存储演进路径(2026-09-29 决策:图片一期本地、二期 COS;视频 COS 直链 + B 站嵌入)、上传链路、后台清洗管理能力。

## 1. 存储演进:URL 永不变

**核心原则:公网图片 URL 从切换日 conglomerate 起永不改变**(`/wp-content/uploads/...`),为 SEO 与正文零改写服务。存储层可换,URL 不动:

```
一期:  /wp-content/uploads/**  ──▶ Nginx ──▶ 本地 workspace/media/ 卷(宿主机持久化,immutable 长缓存)
二期:  同一 URL                ──▶ Nginx ──▶ COS 反代(origin-pull + proxy cache)
       或(更彻底):内容库图片 URL 批量重写为 https://media.17aitech.com/...
       ——内容在自家库,一条 UPDATE 的事;新上传直接写 COS 域路径
```

- `lib/media/storage.ts` 定义 `MediaStorage` 接口(`put/get/delete/stat`),`LocalDiskProvider` 一期实现,`CosProvider` 二期实现——**上层代码零改动**
- 新上传的图片路径规则:一期沿用 `/wp-content/uploads/YYYY/MM/<sha1>.<ext>`(与旧站路径风格一致,前台无差别);切 COS 后改写为 CDN 域路径
- 流量账:一期图片直出服务器(月流量包 1TB 量级,154 篇文章的图量级完全够);**视频从第一天就不落服务器**(下一节)

## 2. 视频:COS 直链 + B 站嵌入(2026-09-29 决策)

| 场景 | 方案 |
|------|------|
| 原创自托管视频(教学/演示录制) | **浏览器 STS 直传 COS → CDN 分发 MP4(`<video>` 原生播放)** |
| 传播型内容 | **B 站嵌入**(iframe;站外流量入口,零存储成本) |
| 视频成为核心内容形态后(更新稳定) | 再立项腾讯云 VOD(转码/HLS/自适应码率),本设计不预支其复杂度 |

**上传链路(关键约束:视频不经应用服务器)**:

1. 后台请求 `POST /api/media/sts` → 服务端用腾讯云 STS SDK 签发**临时上传凭证**(限定 COS 前缀 + 内容长度上限 + 15min 有效)
2. 浏览器 cos-js-sdk-v5 分片直传 COS(断点续传由 SDK 提供)
3. 上传完成回调 `POST /api/media`(带 COS etag/key/size)→ 登记 `content_media`(kind=video,storage=cos)
4. 封面:首帧截取二期用 COS 云端处理(数据万象 `/snapshot/` 参数)或手动上传封面图;一期接受无封面(列表用占位)

- MP4 规范:H.264 + AAC,≤1080p(上传前由后台提示;超规文件一期不做服务端转码,标记 `status=needs_transcode` 提示人工处理)
- `content_media.duration_seconds`:前端上传后用 `<video>` 元数据本地读取回传,不依赖服务端探测
- 文章嵌入:`<VideoPlayer>` 组件双模式(`<video src>` / bilibili iframe),编辑器里粘贴 COS 链接或 B 站链接自动识别

## 3. 后台媒体管理:清洗能力(媒体库页 = 资产管理台)

### 3.1 引用追踪(所有清洗的地基)

- `content_media_ref(media_path, post_id)`:文章保存时由 `lib/media/refs.ts` 解析 content_md(图片/视频语法)与 content_html(`img[src]`、VideoPlayer 数据)提取引用,**先删后插**该文的引用行;封面 cover_path 同步纳入
- 迁移脚本 load 阶段同样为 154 篇旧文建立引用行(与 §03 迁移设计的媒体闭包同源逻辑,复用 `refs.ts`)

### 3.2 三类体检与处置

| 体检 | 定义 | 处置 |
|------|------|------|
| **孤儿**(存储有、无引用) | `content_media.status='orphan'`(audit 任务每日刷新) | 媒体库过滤视图 + 批量删除(软删 7 天回收站再物理删) |
| **断链**(引用了、存储无) | 正文引用路径 ∉ content_media/文件系统 | 每日 audit 列表告警;文章保存时即时校验并提醒 |
| **重复**(同 sha1 多行) | sha1 分组 >1 | 列表展示引用方,一键保留一个、其余改写引用后删除 |

- `GET /api/media/{orphans,duplicates,stats}` 三个端点支撑;`media.audit` BullMQ 定时任务(每日)刷新 status 与统计
- **本次迁移就是第一次清洗**:19GB/5.2 万文件 → 只迁 154 篇引用闭包(预计 <1GB),旧站 94% 媒体不跟随迁移

### 3.3 媒体库后台(src/app/(admin)/admin/media)

- 三 Tab(图片/视频/文件)× 引用状态过滤(全部/已引用/未引用/断链);网格视图,缩略图用 `thumb_path`
- 单条详情:预览、尺寸/大小/时长/sha1、**引用方文章列表**(点进即达)、删除/替换
- 批量操作:删除孤儿、导出重复清单;操作全部走确认弹窗 + 操作日志(pino 记 admin 事件)
- 存储统计卡:按 kind 的数量/体积、近 30 天增量(数据来自 stats 端点,audit 任务落 Redis 缓存)

### 3.4 图片处理管线(一期唯一常驻异步任务)

```
POST /api/media(图片,≤10MB,白名单 jpg/png/webp/gif)
  → LocalDiskProvider.put(原始文件,sha1 命名)
  → queue.add('media.process')  返回 202 + mediaId
worker:sharp 生成 WebP 副本(质量 80)+ 缩略图 640w(thumb_path)
  → 回填 width/height/sha1/status=active;失败重试 3 次后标 error 并在后台告警
```

- 正文插入编辑器时优先引用 WebP 副本(原格式作为降级 `<picture>` source 由 ArticleBody 处理)
- 旧迁移图片不做批量 WebP 重生成(正文 HTML 保真原则);后台提供可选的"重压缩"单条操作

## 4. 纪律汇总

- **请求内禁做秒级以上处理**:图片压缩进 BullMQ;视频根本不进服务器
- 媒体删除必须过引用检查(有引用则拒绝并列出引用方);物理删除只发生在回收站过期后
- `content_media.path` 全站唯一且即 URL 路径——任何"文件挪位置"的需求都通过"新增记录 + 内容改写引用 + 旧记录标 orphan"实现,禁止直接 mv
- COS 凭证:STS 临时凭证下发,永久密钥只在服务端 env;COS 桶策略:读公开(经 CDN)、写仅 STS
