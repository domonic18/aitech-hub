## 1. 项目定位

**Hub 定位(2026-09-30 升级,当前有效)**:站点不再定位为个人博客站,而是 **AI 信息 Hub(聚合平台)**——使命是连接用户与快速变化的 AI 信息。载体覆盖文字(资讯/教程)、短视频(资讯/教程)与长视频(教程);信息形态覆盖资讯、教程与示例项目。博主原创文章是 Hub 的**信息渠道之一**,前台以「博主个人」渠道标识与其他渠道(电报流/短视频解读/开源项目)区分;一期 M1~M6 的博客能力即 Hub 的**文章渠道底座**;品牌与域名不变,GEO 双受众不变;「不追资讯量、做可信信息源」升级为 **Hub 的准入纪律**——所有渠道共用同一套过滤/屏蔽词/治理约束。

**短视频解读版权红线(2026-09-30,全站硬约束)**:转写是输入,不是资产——仅持久化「分析结论、摘要、封面缩略图、原文外链」四样;**不存储/不分发视频原片与完整文稿**,转写文本解读判定后即删;前台展示一律带「原视频 ↗」外链与 AI 生成标注(管道与边界见 [arch/02-data-collection §3](../arch/02-data-collection.md))。

**个人品牌线(2026-09-29 战略定位,Hub 之上继续有效)**:以站长(domonic18,https://github.com/domonic18)的人机协同实战塑造个人影响力与品牌,「文章教用法,仓库给武器」。

- 内容主体:站长原创的 AI 工程实战文章(ClaudeCode / MCP / LLM 训练与评测等)——Hub 的「博主个人」渠道
- 替换对象:现有 WordPress 站(https://17aitech.com/),重写而非改版,公开品牌与域名不变

**战略定位(2026-09-29 评审定稿)**:在上述基础上,站点的演进方向为——
- **「一个人指挥智能体军团的公开实战档案」**:以第一人称、可复现(含失败案例)的人机协同实战为内容主线;产品(资讯管道/渠道分发/建站过程)与内容互相喂养;文章附带可执行资产(CLAUDE.md 模板、skills、MCP 配置、工作流仓库),与 GitHub 联动——**"文章教用法,仓库给武器"**
- **「想了解 AI 的人群的资深可信信息源」**:AI 普及在广度上存在显著信息差(人员素质与地区差异),这是个人站的机会窗口;差异化锚点 = 第一人称 + 可复现 + 可问责(真人验证标记),不追资讯量
- **内容双受众**:文章同时为人与智能体而写——`llms.txt`、文章 md 直出(一期),站点 MCP server(专项),被 AI 引用即新流量入口与品牌放大器
- 付费阅读原则:不卖信息(免费且泛滥),卖经过验证的工作流 + 可复现结果 + 作者问责

## 3. 一期范围(首次上线必须交付)

### 3.1 内容站

- **文章**:列表(分页)、详情、归档(按时间)、分类过滤、标签过滤、站内搜索(标题/摘要 LIKE 或 PG 全文,一期不引入 ES)
- **分类**:沿用旧站四个分类 slug——`blog`(博客文章)、`report`(产品评测);`news`(行业资讯)/`advertising`(推广活动)不迁移内容,但分类路由 `/category/<slug>/` 需保留以承接旧外链 301
- **页面**:首页(最新 + 精选;二期升级为 **Hub 控制台形态**——Agent 搜索输入框 + 电报流 LIVE 带 + 项目展示 + 博主文章,见 §4)、关于(重写)、用户协议、隐私政策(迁移旧文本)
- **浏览量**:展示每篇阅读次数(历史数据聚合迁移,新增实时累计)

### 3.2 SEO 无损迁移(一期最高优先级约束)

- 旧文章 URL(`https://17aitech.com/<中文编码slug>/`)在新站**原样可用**(200,非 301)
- sitemap.xml、robots.txt、RSS(`/feed.xml`,旧 `/feed/` 301 过来)、文章页 JSON-LD 结构化数据、OG 标签
- Yoast 的 title/description 迁移为新站 meta
- 3314 篇弃用资讯的旧 URL 返回 301(目标:文章列表页),不返回 404
- 图片 URL 路径 `/wp-content/uploads/**` 原样保留(零改写红线)
- **智能体可见性(GEO,2026-09-29 纳入一期)**:`/llms.txt` + `/llms-full.txt`(站点结构的 AI 版目录);每篇文章 `.md` 直出(输出清洗后 content_md);为二期"站点 MCP server"预留内容接口

### 3.3 账号体系(2026-09-30 调整:用户短信登录延后三期)

- **延后背景(2026-09-30 评审定)**:运营商签名实名报备不再接纳个人主体——腾讯云自 2025-09-18 起停开「个人自用资质」(个人申请签名须改走「他用资质」,需企业证件 + 授权委托书),阿里云同规公告;个人无企业证件即无法开通国内验证码短信。**用户短信验证码登录、pending_binding 绑定、个人中心整体延后至三期**(触发:企业主体短信资质办结,或替代认证方案——如本机号码认证——立项评审通过)
- **一期仅保留 admin 鉴权**:admin 密码登录(手机号 + password_hash,`npm run admin` 建号时设置)+ jose Cookie 会话 + Redis 吊销;前台无登录入口,游客可读全部非付费内容
- 以下为三期开启时恢复执行的原设计:手机号 + 短信验证码登录/注册合一(验证码 Redis 存储 + 频控);296 个旧用户全量迁移**照常在一期完成**(243 active / 53 pending_binding,2026-09-29 迁移实跑口径:1 例跨用户重复手机号按「保留最早注册者」规则落败),登录通道三期开启;密码不做迁移,用户可在「账号设置」自愿补设;JWT(access + refresh),刷新令牌入 Redis 可吊销;个人中心:昵称/头像/简介编辑、账号设置

### 3.4 管理后台

- 文章管理:列表、创建、编辑、发布/下架(Markdown 优先,支持粘贴旧 HTML 正文渲染)
- **一键发文体验(2026-09-29 需求补充)**:
  - Markdown 导入:粘贴/导入本地 `.md`,自动识别文中全部图片引用;本地图片经「选择文件夹/拖拽/zip」批量上传媒体库并自动替换为站内 URL(sha1 去重);**外链图片一键转存**自有媒体库;编辑器内截图粘贴直接上传
  - 封面工作流:本地上传 + 内置裁剪器,预设模板(微信封面 2.35:1、站内/OG 1200×630、CSDN 16:9),**一次裁剪多尺寸导出**;AI 文生图封面一期预留入口,二期接腾讯云混元生图
- 分类/标签管理、媒体库(列表/上传)
- 用户管理:列表、禁用/启用
- 数据一览并入站点统计页(§3.5)

### 3.5 站点统计(2026-09-29 需求补充)

对标旧站 wp-statistics 插件的后台统计页:站点访问量、来源构成、热门内容一屏可见;同时为 GEO 战略提供「AI 引用量」可观测指标。

- **采集(自有埋点,一期全站)**:前台客户端 beacon 上报(兼容 ISR——缓存页不发服务端计数,客户端上报天然排除服务端缓存);服务端接收 API 做校验/去噪/去 bot;与文章阅读数**同源采集**(文章页 PV 同时累计 `content_post.views_count` 与站点统计,与迁移来的历史阅读数直接累加,口径差异不做折算)
- **后台统计页**:
  - 总览卡片:今日/昨日/近 7 日/近 30 日 PV・UV、累计 PV;文章数/用户数
  - 趋势图:PV/UV 按日曲线(7/30/90 天切换)
  - 流量来源:直接访问 / 搜索引擎(Google、Bing、百度等细分)/ 站外链接 Top N / **AI 助手单独类目**(ChatGPT、Perplexity 等——旧站实测已有此类来源,是 GEO 战略的核心观测指标)
  - 热门页面:今日/7 天/30 天/全部 时间段筛选的访问 Top 文章与页面
  - 访客环境:浏览器/操作系统/设备类型分布(采集一期实现,展示可简版)
- **关键约束**:
  - 不引入第三方统计服务(百度统计/GA/Umami),数据完全自有;旧站即 wp-statistics 自建口径,保持一致
  - UV 用匿名标识(IP+UA 哈希),**不存明文 IP**;隐私政策文本同步说明统计采集
  - 排除口径:管理员登录态、已知爬虫 UA、API 与静态资源请求不计入
  - 聚合存储日粒度;上报与聚合不得影响前台性能(2C4G 量级日万级 PV 无压力)
  - 旧站 `wp_statistics` 明细**不迁移**(visitor 7.4 万行,且旧站 2025-12 才启用该插件),站点级统计自新站上线起算;文章历史阅读数已由 `wp_post_views` 迁移承接

### 3.6 站长发文工作流:本地 Markdown → Claude Code 直接发布(2026-09-29 需求补充)

背景:站长的内容生产方式即「人机协同」——Claude Code 在本地写 md(含本地截图),完成后由 Claude Code 直接发布到站点。这是 requirement §1 战略定位在发布链路的落地,也是二期"发布后自动分发"(微信公众号)的触发起点。

- **架构原则:API 为核,MCP 为壳**——先建 Token 鉴权的发布 API(与后台 UI 同一 service 层),MCP 是该 API 的薄封装;后台 UI / MCP / curl 三条路同一套逻辑,不漂移
- **发布 API(Bearer PAT 鉴权)**:
  - 个人访问令牌(Personal Access Token):`Authorization: Bearer`,库中只存哈希,可吊销、记 `last_used_at`;与后台 Cookie 会话并列为 admin 鉴权的第二种方式,复用同一批 handler
  - `upsert_article`:md 正文 + frontmatter(title/slug/excerpt/category/tags/cover/seo),**按 slug 幂等 UPSERT**——本地 md 是文章唯一真相源,改后重发即更新,不产生重复文章;slug 缺省由标题生成(策略见 arch 文档)
  - **图片随文自动处理**(与 §3.4 一键发文同一管线实现):正文中的本地图片引用随文上传媒体库(sha1 去重)并自动替换为站内 URL;外链图片可选转存
  - 其余工具:`upload_media`(截图先传后引文)、`get_article` / `list_articles`(按状态/时间)、`publish` / `unpublish`;tags 按名自动建立,category 按 slug 挂载
  - 默认落**草稿**,`publish=true` 直发;草稿可在后台预览后人工发布
  - `content_md` 存 md 原文并服务端渲染 `content_html`,与迁移文章的双模式渲染(arch/07-frontend)一致
- **创作 MCP server(一期交付)**:由同一 Next.js 应用托管 Streamable HTTP 端点(如 `/api/mcp`),Bearer PAT 鉴权,暴露上述工具;Claude Code `claude mcp add` 即接。二期对外只读的「站点内容 MCP」与创作 MCP 共用端点、按鉴权区分工具集(见 §4)
- **约束**:全部变更走管理审计日志(以 token 身份记录);令牌仅存站长本地;上传类型/大小白名单与 §6 安全要求一致
